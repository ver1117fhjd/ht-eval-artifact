# Deviations in the HW2VEC / GNN4TJ re-scoring (Sec. V-F)

This note documents every deviation between the released HW2VEC/GNN4TJ pipeline
(github.com/AICPS/hw2vec, HOST'21) and the re-instantiation whose numbers are
reported in Sec. V-F and shipped as `results/ladder_results.csv` and
`results/ladder_report.txt`. The paper cites this file for that reason; no
number in Sec. V-F comes from any other source.

## 1. What was re-scored

* Corpus: the E1 paired set, **87 pairs** (whole pairs excluded together, not
  per-netlist). Source: `tools/hw2vec_ladder/prep_corpus.py`.
* Graph type: **AST** graphs, not DFG. DFG is not merely slower on this corpus, it
  does not run: pyverilog's dataflow pass needs every instantiated cell to be a
  defined module, and the Trust-Hub gate-level netlists instantiate library cells
  (`pyverilog.utils.verror.DefinitionError: No such module: LSDNENX1` on
  `s15850-T100`). Where a design does parse, extraction exceeds 150 s on the
  smallest netlist of the corpus (RS232-T2100) and 240 s on the smallest AES
  variant (AES-T100), versus 2-15 s for AST. This is the largest single deviation
  and the one that most limits the claim: we can say the re-instantiation does not
  reproduce the published scores, not that the released DFG pipeline cannot.
* Splits: the four surviving protocol rungs (pooled random 5-fold,
  group-by-variant, group-by-base, leave-one-family-out), each with 2 training
  seeds × 200 epochs. Source: `tools/hw2vec_ladder/run_ladder.py`.

## 2. Code fixes without which the pipeline does not train

1. **Double log-softmax.** The released training loop applies `log_softmax` and
   then feeds the result to a loss that applies it again, so the loss is pinned
   at ln 2 for all epochs. We use cross-entropy directly on the logits. Without
   this fix the loss is flat, the confusion matrix flips between all-zero and
   all-one predictions, and test accuracy oscillates between 0.38 and 0.67 —
   i.e. no result at all.
2. **Feature scale.** Node features are multiplied by 100 before the first
   convolution; with the released scale the first GCN layer's degree
   normalization drives all activations into the dead ReLU region.
3. **Readout.** Mean readout instead of the released configuration, which does
   not converge at this graph size. (Trojan signal is local, so mean pooling is
   a conservative choice, not a favourable one: an attention or max readout can
   only raise the scores.)

## 3. Result actually obtained (E1, 87 pairs, 2 seeds, 200 epochs)

| Rung | AUC | Specificity |
|---|---|---|
| pooled, random 5-fold | 0.491 ± 0.046 | 0.619 |
| group-by-variant | 0.611 ± 0.007 | 0.690 |
| group-by-base | 0.536 ± 0.037 | 0.726 |
| leave-one-family-out | 0.546 ± 0.032 | 0.679 |

Specificity exceeds sensitivity on every rung (0.62-0.73 vs 0.37-0.49): the
class bias is toward golden designs, not toward Trojan discrimination.

## 4. What this does and does not license

* Licenses: "under our re-instantiation, GNN4TJ reproduces neither its published
  near-perfect scores nor the tree-family cliff" — which is what the paper says,
  and which is offered with an explicit invitation for the authors to re-score
  with their own pipeline.
* Does **not** license: any claim that the released DFG-based pipeline fails on
  the ladder. We did not run it at that graph type.

## 5. How to re-run

    git clone http<local-path> tools/hw2vec      # checkout at tools/
    python tools/hw2vec_ladder/prep_corpus.py                   # corpus -> whole pairs
    python tools/hw2vec_ladder/extract_graphs.py                # AST graphs -> cache
    python tools/hw2vec_ladder/run_ladder.py                    # 4 rungs x 2 seeds

The scripts resolve their root as `Path(__file__).resolve().parents[2]`, so they
must sit at `<root>/tools/hw2vec_ladder/` with the HW2VEC checkout at
`<root>/tools/hw2vec/`. The trained checkpoint (`model.pth`, 232 KB) is not
shipped: it is regenerated by `run_ladder.py` and is not needed to reproduce the
table. The full training log (4.2 MB) is likewise omitted; the per-rung summary
in `results/ladder_report.txt` is the authoritative record.

## 6. Measured: why DFG cannot be run on this corpus (2026-10-23)

Measured on the artifact machine (CPU-only), smallest design in the corpus,
`TjFree/RS232__RS232-T2100` (11.4 KB of Verilog, three source files):

| graph type | nodes | edges | wall time |
|---|---|---|---|
| AST | 402 | 401 | **1.1 s** |
| DFG | -- | -- | **>611 s, killed** (not finished) |

The released front-end is PyVerilog's dataflow pass; on the corpus it does not
terminate on a design that the AST pass finishes in about a second, and the
designs are 2-3 orders of magnitude larger elsewhere in the corpus (AES,
WB_CONMAX). A full DFG re-scoring of the 87 pairs is therefore not attainable
with the released tool, which is why Sec. V-F re-scores in AST mode.

The released *model and training loop* do run: `examples/use_case_2.py` on the
release's own `assets/TJ-RTL-toy` with DFG graphs (unmodified except for three
platform/version fixes: Windows path split, `sklearn.compute_class_weight`
keyword arguments, `np.Inf`->`np.inf`) reaches train accuracy 0.889 / F1 0.917
and best test accuracy 1.000 / F1 1.000 on the 20-graph toy set. So the
re-instantiation is not blocked by the model code.
